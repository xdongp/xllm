## 第一篇：搭建一个Demo推理引擎

### 前言

在当今AI发展的风口，大型语言模型（LLM）已经成为各种应用的核心技术。然而，要真正理解LLM的工作原理，最好的方法就是从头开始编写一个推理引擎。学习一千遍，还不如自己动手做一次来得实际。本文将详细介绍如何搭建一个简单的LLM推理引擎Demo，帮助大家深入理解LLM推理的基本原理和实现方式。以流行的Qwen模型为例，一步步解释如何构建推理引擎。

### 为什么需要自己编写推理引擎？

虽然市面上有许多成熟的LLM推理框架，如vLLM、SGLang等，但自己动手编写推理引擎有以下优势：

1. **深入理解LLM推理的内部机制**：从底层理解模型加载、提示处理、生成等关键环节
2. **掌握核心组件**：了解分词器、模型、解码器等组件的协作方式
3. **为性能优化打下基础**：理解瓶颈所在，为后续优化指明方向
4. **灵活性和可定制性**：可以根据需求自由扩展功能

### 1. 项目结构设计

首先，我们需要设计一个清晰的项目结构。对于一个LLM推理引擎，最基本的部分包括：

- **模型加载模块**：负责加载预训练模型和分词器
- **提示工程模块（Prompt Engineering）**：负责处理用户输入的提示
- **解码模块（Decoding）**：负责生成文本输出
- **交互界面**：提供用户交互接口

### 2. 核心组件实现

#### 2.1 模型加载模块

模型加载是整个推理引擎的基础。我们需要加载预训练模型和对应的分词器：

```python
def load_model(model_path, device="cuda" if torch.cuda.is_available() else "cpu"):
    """加载模型和分词器"""
    print(f"Loading model from {model_path}...")
    print(f"Using device: {device}")
    
    # 检查模型路径是否存在
    if not os.path.exists(model_path):
        raise FileNotFoundError(f"Model path {model_path} does not exist")
    
    # 加载分词器
    try:
        tokenizer = AutoTokenizer.from_pretrained(model_path, trust_remote_code=True)
    except Exception as e:
        print(f"Error loading tokenizer: {e}")
        raise
    
    # 加载模型
    try:
        model = AutoModelForCausalLM.from_pretrained(
            model_path,
            torch_dtype="auto",
            trust_remote_code=True
        )
        # 手动将模型移动到指定设备
        model = model.to(device)
    except Exception as e:
        print(f"Error loading model: {e}")
        raise
    
    model.eval()
    print("Model loaded successfully!")
    return model, tokenizer
```

**关键点说明**：

1. **`trust_remote_code=True`**：允许加载包含自定义代码的模型，这对于一些特定模型（如Qwen）是必需的
2. **`torch_dtype="auto"`**：自动选择合适的数据类型（如float16、bfloat16等）
3. **手动设备管理**：不使用`device_map="auto"`，而是手动将模型移动到指定设备，这样可以避免依赖额外的accelerate库
4. **`model.eval()`**：将模型设置为评估模式，这对于推理是必需的

**推荐模型**：建议使用Qwen3-0.6B，这是一个较小的模型，测试起来比较方便，同时也能展示完整的功能。

#### 2.2 提示工程模块（Prompt Engineering）

提示工程是LLM推理中的关键环节，它负责将用户输入转换为模型可以理解的格式。我们创建一个`PromptEngineer`类来处理这个过程：

```python
class PromptEngineer:
    """负责提示工程处理的类"""
    
    def __init__(self, tokenizer):
        self.tokenizer = tokenizer
    
    def format_chat_prompt(self, history: List[Dict[str, str]]) -> str:
        """使用分词器的chat模板格式化对话历史"""
        try:
            # 尝试使用chat模板
            formatted_prompt = self.tokenizer.apply_chat_template(
                history,
                tokenize=False,
                add_generation_prompt=True
            )
            return formatted_prompt
        except Exception:
            # 如果没有chat模板，则手动构建
            prompt = ""
            for turn in history:
                if turn["role"] == "user":
                    prompt += f"User: {turn['content']}\n"
                elif turn["role"] == "assistant":
                    prompt += f"Assistant: {turn['content']}\n"
            prompt += "Assistant:"
            return prompt
    
    def apply_prompt_template(self, user_input: str, template_type: str = "default") -> str:
        """应用特定的提示模板"""
        if template_type == "question_answering":
            return f"请回答以下问题：{user_input}\n答案："
        elif template_type == "instruction_following":
            return f"请按照以下指示操作：{user_input}\n结果："
        elif template_type == "creative_writing":
            return f"请创作一段关于'{user_input}'的内容："
        else:
            return user_input  # 默认情况下直接返回用户输入
    
    def preprocess_input(self, text: str) -> str:
        """预处理输入文本"""
        # 移除多余的空白字符
        text = " ".join(text.split())
        return text
```

这个类实现了三个主要功能：

1. **`format_chat_prompt`**：处理对话历史，生成模型可以理解的格式
   - 优先使用分词器的chat模板
   - 如果没有chat模板，则回退到手动构建格式

2. **`apply_prompt_template`**：应用特定的提示模板，以适应不同任务类型
   - 支持多种模板：问答、指令跟随、创意写作等
   - 可以轻松扩展新的模板类型

3. **`preprocess_input`**：预处理用户输入，清理格式
   - 移除多余的空白字符
   - 可以扩展更多的预处理逻辑

#### 2.3 解码模块（Decoding）

解码模块负责根据输入生成文本输出：

```python
class Decoder:
    """负责模型解码的类"""
    
    def __init__(self, model, tokenizer):
        self.model = model
        self.tokenizer = tokenizer
    
    def decode(self, input_ids, generation_params: Dict[str, Any]) -> str:
        """执行解码生成"""
        try:
            with torch.no_grad():
                outputs = self.model.generate(
                    input_ids,
                    max_new_tokens=generation_params["max_new_tokens"],
                    temperature=generation_params["temperature"],
                    top_p=generation_params["top_p"],
                    repetition_penalty=generation_params["repetition_penalty"],
                    do_sample=generation_params["do_sample"]
                )
            
            # 解码输出 - 只解码新生成的部分
            response = self.tokenizer.decode(outputs[0][input_ids.shape[1]:], skip_special_tokens=True)
            return response
        except Exception as e:
            # 重新抛出异常，让调用者处理
            raise
```

**关键点说明**：

1. **`torch.no_grad()`**：禁用梯度计算，节省内存并提高推理速度
2. **生成参数控制**：
   - `max_new_tokens`：控制生成的最大token数量
   - `temperature`：控制生成的随机性，较低值产生更确定性输出
   - `top_p`：核采样参数，控制采样的概率范围
   - `repetition_penalty`：控制重复内容的惩罚
   - `do_sample`：是否使用采样（True）或贪婪解码（False）

3. **只解码新生成的部分**：`outputs[0][input_ids.shape[1]:]` 确保只返回模型生成的内容，不包括输入部分

4. **`skip_special_tokens=True`**：跳过特殊标记（如`<|endoftext|>`），使输出更干净

### 3. 传统模式（非PD分离）

在介绍PD分离架构之前，让我们先看看传统的实现方式。传统模式将所有逻辑集中在一个函数中，没有明确的职责分离：

```python
def chat_with_model_original(model, tokenizer, device, generation_params):
    """原有的交互模式（保持向后兼容）"""
    print("\n" + "="*50)
    print("欢迎使用Qwen模型交互式问答!")
    print("当前生成参数:")
    for key, value in generation_params.items():
        print(f"  {key}: {value}")
    print("\n命令:")
    print("  'quit' 或 'exit' - 退出程序")
    print("  'clear' - 清除对话历史")
    print("  'help' - 显示帮助信息")
    print("  'params' - 显示当前参数设置")
    print("="*50 + "\n")
    
    # 设置对话历史
    history = []
    
    while True:
        # 获取用户输入
        try:
            user_input = input("User: ").strip()
        except KeyboardInterrupt:
            print("\n\nGoodbye!")
            break
        
        # 检查特殊命令
        if user_input.lower() in ['quit', 'exit']:
            print("Goodbye!")
            break
            
        if user_input.lower() == 'clear':
            history.clear()
            print("对话历史已清除。\n")
            continue
            
        if user_input.lower() == 'help':
            print("命令:")
            print("  'quit' 或 'exit' - 退出程序")
            print("  'clear' - 清除对话历史")
            print("  'help' - 显示帮助信息")
            print("  'params' - 显示当前参数设置")
            print("  其他输入将作为问题发送给模型\n")
            continue
            
        if user_input.lower() == 'params':
            print("当前生成参数:")
            for key, value in generation_params.items():
                print(f"  {key}: {value}")
            print()
            continue
            
        if not user_input:
            continue
            
        # 构建对话历史
        history.append({"role": "user", "content": user_input})
        
        # 使用分词器的chat模板格式化输入
        try:
            # 尝试使用chat模板
            inputs = tokenizer.apply_chat_template(
                history,
                tokenize=True,
                add_generation_prompt=True,
                return_tensors="pt"
            ).to(model.device)
        except Exception:
            # 如果没有chat模板，则直接编码
            text = user_input
            inputs = tokenizer(text, return_tensors="pt").to(model.device)
        
        # 生成回复
        try:
            with torch.no_grad():
                outputs = model.generate(
                    inputs,
                    max_new_tokens=generation_params["max_new_tokens"],
                    temperature=generation_params["temperature"],
                    top_p=generation_params["top_p"],
                    repetition_penalty=generation_params["repetition_penalty"],
                    do_sample=generation_params["do_sample"]
                )
                
            # 解码输出
            response = tokenizer.decode(outputs[0][inputs.shape[1]:], skip_special_tokens=True)
            
            # 添加到历史记录
            history.append({"role": "assistant", "content": response})
            
            # 打印回复
            print(f"Assistant: {response}\n")
        except Exception as e:
            print(f"生成回复时出错: {e}")
            # 移除最后添加的用户输入，避免历史记录不一致
            history.pop()
            print()
```

**传统模式的特点**：

1. **简单直接**：所有逻辑在一个函数中，容易理解
2. **快速开发**：适合快速原型和简单场景
3. **职责混乱**：提示处理、模型调用、解码等逻辑混在一起
4. **难以扩展**：添加新功能需要修改核心逻辑
5. **测试困难**：无法独立测试各个组件
6. **代码复用性差**：提示处理逻辑无法在其他场景复用

**传统模式的局限性**：

- ❌ **提示处理逻辑耦合**：无法灵活切换不同的提示模板
- ❌ **解码逻辑固化**：难以实现不同的解码策略
- ❌ **扩展性差**：添加新功能（如RAG、多模态）需要大量修改
- ❌ **维护成本高**：随着功能增加，代码会变得难以维护

### 4. PD分离架构设计

在我们的Demo中，我们采用PD（Prompt Engineering + Decoding）分离架构，这是一种将提示工程和解码过程分离的设计模式：

```python
def chat_with_model_pd_separation(model, tokenizer, device, generation_params):
    """与模型进行交互式对话（PD分离版本）"""
    
    # 初始化PD组件
    prompt_engineer = PromptEngineer(tokenizer)
    decoder = Decoder(model, tokenizer)
    
    # 设置对话历史和当前模板
    history = []
    current_template = "default"
    
    while True:
        # 获取用户输入
        user_input = input("User: ").strip()
        
        # PD分离处理流程
        # 1. Prompt Engineering阶段
        # 预处理输入
        processed_input = prompt_engineer.preprocess_input(user_input)
        
        # 应用提示模板
        templated_input = prompt_engineer.apply_prompt_template(processed_input, current_template)
        
        # 构建对话历史
        history.append({"role": "user", "content": templated_input})
        
        # 格式化完整的提示
        formatted_prompt = prompt_engineer.format_chat_prompt(history)
        
        # 编码输入
        inputs = tokenizer(formatted_prompt, return_tensors="pt").to(model.device)
        # 获取实际的输入张量
        input_ids = inputs["input_ids"]
        
        # 2. Decoding阶段
        # 执行解码
        response = decoder.decode(input_ids, generation_params)
        
        # 添加到历史记录
        history.append({"role": "assistant", "content": response})
        
        # 打印回复
        print(f"Assistant: {response}\n")
```

**PD分离架构的优势**：

1. **模块化**：提示工程和解码过程可以独立优化和测试
2. **可扩展性**：可以针对不同任务类型定制提示模板
3. **可维护性**：代码结构清晰，易于调试和修改
4. **职责分离**：每个组件专注于自己的职责，符合单一职责原则

### 6. 命令行参数配置

为了提高灵活性，我们使用命令行参数来配置推理引擎：

```python
def main():
    parser = argparse.ArgumentParser(description="Run Qwen model demo with PD separation")
    parser.add_argument(
        "--model-path",
        type=str,
        default=os.environ.get("QWEN_MODEL_PATH", ""),
        help="Path to the Qwen model directory (can also be set via QWEN_MODEL_PATH environment variable)"
    )
    parser.add_argument(
        "--device",
        type=str,
        default="cuda" if torch.cuda.is_available() else "cpu",
        help="Device to run the model on (cuda/cpu)"
    )
    
    # 生成参数
    parser.add_argument(
        "--max-new-tokens",
        type=int,
        default=512,
        help="Maximum number of new tokens to generate"
    )
    parser.add_argument(
        "--temperature",
        type=float,
        default=0.7,
        help="Sampling temperature"
    )
    parser.add_argument(
        "--top-p",
        type=float,
        default=0.8,
        help="Top-p sampling parameter"
    )
    parser.add_argument(
        "--repetition-penalty",
        type=float,
        default=1.05,
        help="Repetition penalty"
    )
    parser.add_argument(
        "--do-sample",
        action="store_true",
        default=True,
        help="Whether to use sampling for generation"
    )
    
    # PD分离相关参数
    parser.add_argument(
        "--pd-separation",
        action="store_true",
        help="Enable PD (Prompt Engineering + Decoding) separation mode"
    )
    
    args = parser.parse_args()
    
    # 检查是否提供了模型路径
    if not args.model_path:
        print("错误: 请通过 --model-path 参数指定模型路径或设置 QWEN_MODEL_PATH 环境变量")
        sys.exit(1)
    
    # 构建生成参数字典
    generation_params = {
        "max_new_tokens": args.max_new_tokens,
        "temperature": args.temperature,
        "top_p": args.top_p,
        "repetition_penalty": args.repetition_penalty,
        "do_sample": args.do_sample
    }
    
    try:
        # 加载模型
        model, tokenizer = load_model(args.model_path, args.device)
        
        # 根据参数决定使用哪种交互模式
        if args.pd_separation:
            # 使用PD分离模式
            chat_with_model_pd_separation(model, tokenizer, args.device, generation_params)
        else:
            # 使用原有模式（为了向后兼容）
            chat_with_model_original(model, tokenizer, args.device, generation_params)
        
    except KeyboardInterrupt:
        print("\n\n程序被用户中断")
    except Exception as e:
        print(f"发生错误: {str(e)}")
        sys.exit(1)
```

### 8. 关键技术要点

在实现这个Demo推理引擎时，有几个关键技术要点需要注意：

#### 7.1 模型加载
- 正确设置`trust_remote_code=True`以支持自定义模型
- 使用`torch_dtype="auto"`自动选择合适的数据类型
- 手动管理设备，避免依赖额外的库

#### 7.2 输入处理
- `tokenizer()`返回的是`BatchEncoding`对象，需要提取`input_ids`
- 确保输入张量和模型在同一个设备上
- 正确处理对话历史和chat模板

#### 7.3 内存管理
- 使用`torch.no_grad()`避免梯度计算，节省内存
- 在推理时使用`model.eval()`模式
- 只解码新生成的部分，避免重复解码

#### 7.4 错误处理
- 添加适当的异常处理机制
- 在出错时保持对话历史的一致性
- 提供清晰的错误信息

#### 7.5 特殊token处理
- 使用`skip_special_tokens=True`避免输出特殊标记
- 正确处理pad token和eos token
